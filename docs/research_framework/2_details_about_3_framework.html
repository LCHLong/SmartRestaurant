Ba framework cho hội thoại AI thời gian thực

Tổng hợp và đối chiếu hai bản báo cáo nghiên cứu độc lập về Pipecat, LiveKit và TEN Framework — ba nền tảng mã nguồn mở để xây dựng tác nhân (agent) giọng nói và đa phương thức thời gian thực — cùng phần phụ lục về chuẩn hóa HTML và thực hành tốt khi xây giao diện cho các ứng dụng này.

00 Tóm tắt điều hành

Cả hai báo cáo đều thống nhất: Pipecat, LiveKit và TEN đều là framework mã nguồn mở phục vụ xây dựng ứng dụng hội thoại giọng nói / đa phương thức với AI, nhưng khác nhau rõ rệt về triết lý kiến trúc — pipeline Python linh hoạt, nền tảng hội nghị SFU quy mô lớn, hay đồ thị extension đa ngôn ngữ tối ưu độ trễ. Một trong hai tài liệu nguồn còn bổ sung phần phụ lục về các chuẩn HTML (WHATWG/W3C, WCAG, bảo mật CSP) áp dụng cho lớp giao diện web của các hệ thống này.

Pipecat

Framework Python điều phối >150 dịch vụ AI (STT/LLM/TTS) trong một pipeline thời gian thực, ưu tiên độ trễ thấp và dễ đổi nhà cung cấp.

LiveKit

Nền tảng SFU WebRTC cho hội nghị đa người, tích hợp Agents Framework để đưa tác nhân AI vào phòng như một người tham gia.

TEN

Framework đa ngôn ngữ (C++/Go/Python/TS) tổ chức ứng dụng thành đồ thị extension, tách riêng "đường nóng" hiệu năng cao để đạt độ trễ cực thấp.

01 Pipecat

Pipecat.ai

pipecat.daily.co

Hệ sinh thái Python mã nguồn mở để xây dựng trợ lý giọng nói và ứng dụng AI đa phương thức, điều phối hơn 150 dịch vụ AI (STT, LLM, TTS, nhận dạng hình ảnh…) trong một pipeline duy nhất nhằm đạt hội thoại tự nhiên, phản hồi nhanh (round-trip khoảng 500–800ms).

Kiến trúc & thành phần

Kiến trúc tách client (JS/React/React Native/iOS/Android/C++) và server Python chạy pipeline theo khung audio (frame): Transport (WebRTC/SIP/PSTN) → STT → LLM → TTS → phát lại. Hệ thống dùng mô hình đa tác nhân — mỗi agent là một tiến trình/luồng, phối hợp qua message bus (Redis hoặc PostgreSQL), quản lý bởi WorkerRunner, lớp cơ bản BaseWorker, và các worker chuyên biệt (PipelineWorker, LLMWorker). "Pipecat Flows" cho phép định nghĩa luồng hội thoại theo trạng thái (đặt vé, thu thập thông tin, xác nhận…) thay vì để LLM tự do ứng xử. Giao tiếp client–server tuân theo giao thức RTVI (Real-Time Voice Inference), giúp tương thích với các server khác cùng chuẩn.

Ví dụ tích hợp web (JavaScript)

import { PipecatClient, PipecatRTCTransport } from '@pipecat/client';

const client = new PipecatClient({
  startUrl: "https://api.pipecat.daily.co/v1/public/my-agent/start",
  transport: new PipecatRTCTransport(),
  publicApiKey: "YOUR_API_KEY"
});
await client.connect();
client.on('transcript', t => console.log("Bot nói:", t));
await client.sendText("Xin chào");
Triển khai
Tự host (Python 3.11+, tối thiểu ~2 CPU/4GB RAM) hoặc Pipecat Cloud (Daily) — quản lý toàn phần, tự động scale ngang; gói Enterprise chạy trong AWS/GCP/Azure riêng của doanh nghiệp.
Hiệu năng
Round-trip điển hình ~0.5–0.8s. Vì chạy trên Python/asyncio, tác vụ CPU nặng (lọc nhiễu, DSP, embedding) cần đẩy ra executor hoặc native extension để tránh giật khung audio.
Bảo mật
TLS cho kết nối, xác thực bằng API key (public bot endpoint) hoặc JWT (Pipecat Cloud). Khuyến nghị dùng CSP chống XSS, sanitize HTML người dùng nhập (ví dụ DOMPurify), mã hóa dữ liệu nhạy cảm khi lưu trữ để tuân GDPR/CCPA.
Giấy phép / giá
BSD 2-Clause — miễn phí, tự do dùng và phân phối. Pipecat Cloud tính theo phút: gói agent 1x/2x/3x (0.5–1.5 vCPU) ~$0.01–0.03/phút hoạt động; vận chuyển WebRTC giọng nói ~$0.001/phút, video ~$0.004/phút/người; SIP/PSTN ~$0.003–0.018/phút. Miễn phí 10.000 phút/tháng đầu.
Phù hợp khi
Cần tùy biến sâu pipeline hội thoại, đổi nhanh nhà cung cấp AI, xử lý song song nhiều tác vụ, hoặc xây logic hội thoại có kịch bản phức tạp (flows). Ví dụ: trợ lý thoại, tổng đài AI, bot đa kênh, game giọng nói.
⚠ Điểm yếu chính: phụ thuộc Python (GIL/asyncio) nên logic nặng dễ gây nghẽn; hạ tầng bus (Redis/Postgres) cần vận hành thêm khi scale đa node; tính năng video/đa phương thức còn sơ khai hơn LiveKit.

02 LiveKit

LiveKit.com

livekit.io

Nền tảng mã nguồn mở và dịch vụ đám mây cho truyền thông thời gian thực (WebRTC SFU) kết hợp Agents Framework để đưa tác nhân AI vào phòng họp như một người tham gia thực thụ — phục vụ cả hội nghị đa người và trợ lý ảo.

Kiến trúc & thành phần

LiveKit Server là SFU (Selective Forwarding Unit) viết bằng Go, xử lý signaling, NAT traversal, mã hóa DTLS-SRTP, hỗ trợ simulcast và nhiều codec (VP8/H.264/AV1); một instance phục vụ khoảng 300–500 người tham gia trước khi cần chia node, và có thể cluster qua Redis để scale lên hàng nghìn kết nối. Agents Framework cho phép viết tác nhân Python/Node gia nhập phòng, nhận audio/video, chạy qua STT→LLM→TTS rồi phát lại — hỗ trợ turn-taking ngữ nghĩa và dispatch API. Hệ sinh thái SDK rất rộng: client (JS/React, Swift, Kotlin, Flutter, Unity, React Native, C++) và server (Go, Node, Python, Rust, Ruby, Java, PHP), cùng REST/Twirp API (CreateRoom, JoinRoom, UpdateParticipant…) và các dịch vụ phụ trợ: egress/ingress (ghi/nhập luồng RTMP-SRT), Telephony SIP/PSTN, DTMF, call transfer.

Ví dụ kết nối phòng (JavaScript)

import { Room } from 'livekit-client';

const room = new Room();
await room.connect("wss://<your-livekit-server>", token); // token do backend cấp
room.on('trackSubscribed', track => {
  // gắn track lên DOM hoặc xử lý dữ liệu
});
Triển khai
Tự host (binary/Docker/Kubernetes, ~2 CPU/4GB RAM tối thiểu) hoặc LiveKit Cloud đa vùng với SLA — cùng một API cho cả hai môi trường, front-end không đổi khi chuyển từ local lên cloud.
Hiệu năng
Độ trễ đầu-cuối thực tế ~100–250ms, đủ thấp cho hội thoại tự nhiên; kiến trúc SFU phi tập trung đã chứng minh phục vụ hàng nghìn kết nối đồng thời.
Bảo mật
Mã hóa media qua SRTP, tín hiệu qua HTTPS/WebSocket/TLS; xác thực bằng JWT (API key + secret) theo từng phòng/người tham gia. Khuyến nghị CSP dạng default-src 'self'; frame-ancestors 'none'; để chặn clickjacking/XSS. Cloud có SOC2/GDPR tùy gói; tự host cho toàn quyền kiểm soát dữ liệu (phù hợp yêu cầu HIPAA).
Giấy phép / giá
Apache 2.0 — miễn phí khi tự host. LiveKit Cloud tính theo phút tham gia: ~$0.004/phút (audio), ~$0.016/phút (video), ghi hình (egress) ~$0.024/phút; các gói dịch vụ từ miễn phí đến $50–500+/tháng cộng phí sử dụng.
Phù hợp khi
Cần hội nghị đa điểm, tích hợp đa kênh voice-video, mở rộng toàn cầu, hoặc kết hợp điện thoại truyền thống (SIP/PSTN) với AI. Ví dụ: hội nghị trực tuyến, telehealth, giáo dục từ xa, AI Meeting Assistant, call bot doanh nghiệp.
⚠ Điểm yếu chính: học phí kiến trúc phòng/track/worker khá cao cho đội nhỏ chỉ cần bot thoại 1-1; cần hiểu WebRTC (TURN, NAT traversal); quản lý trạng thái ở quy mô hàng nghìn phòng đòi hỏi Redis cluster và cân bằng tải kỹ lưỡng.

03 TEN Framework

TEN (theten.ai)

Transformative Extensions Network

Framework mở, đa ngôn ngữ hướng tới hệ thống tác nhân đa phương thức thời gian thực, được Agora hậu thuẫn. Ứng dụng được tổ chức như một đồ thị định hướng (graph) gồm nhiều extension, cho phép tách phần xử lý cần hiệu năng cao sang ngôn ngữ biên dịch (C/C++/Go) trong khi logic tổng thể vẫn viết bằng Python/TypeScript.

Kiến trúc & thành phần

Tệp property.json định nghĩa đồ thị extension, quy tắc định tuyến và trạng thái agent. Mỗi extension (viết bằng C/C++, Go, Python hoặc TypeScript) đảm nhiệm một công đoạn: VAD, STT, LLM, TTS, xử lý hình ảnh… TEN tích hợp sẵn TEN VAD (Voice Activity Detection nhẹ, ~300KB, hop 10ms) và TEN Turn Detection để nhận biết ngắt lời tự nhiên. Một server backend (Go) tiếp nhận yêu cầu HTTP/WebSocket, khởi chạy và định tuyến agent process; đi kèm Playground — giao diện web (cổng 3000) để cấu hình/debug trực quan, cùng bộ công cụ TMAN Designer/CLI để dựng đồ thị extension bằng kéo-thả.

Ví dụ gọi API (JavaScript)

fetch("http://localhost:8080/api/v1/chat", {
  method: "POST",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({ text: "Xin chào" })
})
.then(res => res.json())
.then(data => console.log("Bot:", data.reply));
Triển khai
Hoàn toàn tự host (Docker, Kubernetes, VM local hoặc edge) — không có dịch vụ cloud chính thức. Yêu cầu tối thiểu nhẹ (~2 CPU/4GB RAM cho agent cơ bản); có thể chạy một phần trên thiết bị edge (ví dụ ESP32-S3) và phần còn lại trên cloud.
Hiệu năng
Tối ưu "đường nóng" bằng native code nên độ trễ VAD/DSP rất thấp; overhead chủ yếu ở serialization khi chuyển frame giữa các extension khác ngôn ngữ, nên hiệu năng phụ thuộc thiết kế đồ thị (càng ít copy dữ liệu càng tốt). TEN chưa có hệ scale phân tán sẵn như LiveKit; mở rộng chủ yếu bằng cách nhân bản server/instance.
Bảo mật
Endpoint API cần HTTPS/CORS tự cấu hình; vì extension có thể chạy mã tùy ý, môi trường nên cô lập bằng Docker/sandbox. Cần lọc đầu vào nếu người dùng có thể gửi lệnh cấu hình extension, tránh chèn mã nguy hại.
Giấy phép / giá
Apache 2.0 kèm điều khoản bổ sung của Agora (hạn chế xây dịch vụ cạnh tranh và một số ràng buộc khi cài trên thiết bị người dùng). Miễn phí hoàn toàn khi tự host; cộng đồng GitHub hơn 11k sao, có Discord hỗ trợ.
Phù hợp khi
Cần độ trễ siêu thấp, xử lý đồng thời audio + video + dữ liệu, chạy trên thiết bị edge/IoT/robot, hoặc đội ngũ đa ngôn ngữ (Python + C++) muốn kiểm soát hoàn toàn luồng AI. Ví dụ: thông dịch song ngữ thời gian thực, robot nhận dạng cảnh vật, voice agent nhúng.
⚠ Điểm yếu chính: độ phức tạp phát triển cao (lỗi native khó debug, phụ thuộc ABI/toolchain đa ngôn ngữ); cộng đồng và tài liệu còn non trẻ hơn Pipecat/LiveKit; điều khoản giấy phép bổ sung của Agora cần lưu ý khi triển khai thương mại quy mô lớn.

05 Checklist đánh giá & PoC đề xuất

Trước khi chọn framework, nên xây dựng Proof of Concept và đối chiếu theo checklist sau (đo bằng latency, dropout rate, tốc độ nhận dạng, FPS video nếu có, và chi phí/phút).

1

Kiểm thử tính năng chính

Xây kịch bản dùng khả năng đặc trưng của mỗi framework; đo độ trễ đầu-cuối, độ trễ từng thành phần (STT/LLM/TTS), khả năng xử lý đồng thời.

2

Đánh giá quy mô

Load test nhiều kết nối đồng thời để đo throughput, CPU/RAM, băng thông; xác định giới hạn mỗi framework (số flows/phòng tối đa).

3

Tích hợp & linh hoạt

Thử đổi nhà cung cấp STT/TTS/LLM mà không sửa code nhiều; đánh giá tích hợp với hệ sinh thái hiện có (DB, CRM, RAG).

4

Độ ổn định & an toàn

Kiểm tra khả năng khôi phục khi mất mạng/restart; xác thực, mã hóa audio, chống tấn công token.

5

Chi phí & triển khai

Tính chi phí hạ tầng tự host (server, CPU/RAM, GPU) so với giá dịch vụ cloud tương ứng.

6

Trải nghiệm người dùng

Mô phỏng gọi thực tế từ trình duyệt/điện thoại; theo dõi chất lượng âm thanh và khả năng xử lý ngắt lời.

Gợi ý sơ đồ thử nghiệm: LiveKit — 1–3 node SFU + Redis cluster + agent server Python; Pipecat — 2 worker + 1 Redis bus + TTS/ASR giả lập; TEN — 1 instance server + các extension Python/C++ giả lập. Ưu tiên tốc độ phát triển và quy mô rộng → LiveKit; ưu tiên tùy biến sâu và đa mô-đun → Pipecat hoặc TEN.

06 Phụ lục: Chuẩn hóa HTML & thực hành tốt

Phần bổ sung riêng của một trong hai tài liệu nguồn, liên quan tới lớp giao diện web mà các framework trên đều cần (client SDK, Playground, dashboard).

Tiêu chuẩn chính thức (WHATWG / W3C)

HTML được chuẩn hóa dưới sự hợp tác của WHATWG (duy trì "HTML Living Standard", hướng tới ngôn ngữ đánh dấu ngữ nghĩa cho web có truy cập cao) và W3C (khuyến nghị HTML5 năm 2014, bổ sung phần tử/API mới như video, audio, canvas, localStorage). Các thẻ ngữ nghĩa như <section>, <article>, <nav>, <header>, <footer> ra đời từ đây.

Phần tử ngữ nghĩa (Semantic HTML)

Dùng đúng phần tử cho đúng mục đích để tận dụng các hỗ trợ truy cập có sẵn của trình duyệt — ví dụ <button> thay vì <div> để tự động hỗ trợ điều hướng bàn phím và ARIA cơ bản. Hệ thống heading và các thẻ cấu trúc giúp screen reader và công cụ SEO nhận biết nội dung dễ dàng hơn, đồng thời HTML ngữ nghĩa thường nhẹ và responsive hơn.

Truy cập & WCAG

WCAG đề xuất bốn nguyên tắc: Perceivable, Operable, Understandable, Robust — bảo đảm văn bản thay thế (alt) cho hình ảnh, tiêu đề hợp lý, nhãn form rõ ràng, và điều khiển được bằng bàn phím, giúp nội dung tiếp cận được nhiều nhóm người khuyết tật hơn.

Bảo mật: CSP & sanitization

Content Security Policy (CSP) giúp ngăn chặn script không rõ nguồn — lớp phòng thủ thứ cấp chống XSS. Với nội dung HTML do người dùng tạo (WYSIWYG), cần sanitize đầu ra (ví dụ DOMPurify); dùng .textContent thay vì gán HTML thô để tự động encode ký tự an toàn.

Ví dụ cấu trúc HTML5 chuẩn kèm CSP

<!DOCTYPE html>
<html lang="vi">
  <head>
    <meta charset="UTF-8">
    <title>Ví dụ trang</title>
    <meta http-equiv="Content-Security-Policy" content="default-src 'self';">
  </head>
  <body>
    <header>
      <h1>Tiêu đề chính</h1>
      <nav><!-- menu điều hướng --></nav>
    </header>
    <main>
      <article>
        <h2>Phần nội dung</h2>
        <p>Nội dung chính.</p>
      </article>
      <aside>Thông tin phụ</aside>
    </main>
    <footer>&copy; 2026 Công ty ABC</footer>
  </body>
</html>
Nguồn

Nội dung được tổng hợp và hợp nhất từ hai báo cáo nghiên cứu độc lập ("deep-research-report.md" và bản sao có phần phụ lục HTML) do người dùng cung cấp, dựa trên tài liệu chính thức và các bài viết chuyên sâu về Pipecat, LiveKit và TEN Framework, cùng tài liệu chuẩn của WHATWG, W3C, MDN, WCAG và OWASP.
